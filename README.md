# Тест на 5 паттернов — Telegram-бот

Бот по ТЗ: квиз из 8 вопросов → результат → рабочий приём → оффер диагностической сессии → запись на слот.

## Чем это отличается от исходного ТЗ

В ТЗ запись строилась на TidyCal (тариф Individual, $29 разово). Раз платный сервис не подходит, я убрала внешний сервис полностью: бот сам ведёт расписание. Ты один раз добавляешь свободные окна командой в чате с ботом, дальше пользователь видит их кнопками, выбирает время — бот сразу бронирует слот и присылает тебе уведомление в этот же Telegram-чат со всеми данными для дальнейшей ручной связи (оплата, созвон). Никакого API, вебхуков и Zapier не нужно — то, ради чего в ТЗ был нужен платный тариф TidyCal, здесь просто не требуется.

Плата за это — три вещи, которые раньше делал TidyCal сам: слоты в расписание добавляешь вручную (команда занимает секунды), автоматической синхронизации с твоим личным календарём нет, и email-подтверждений клиенту TidyCal тоже не шлёт — вместо этого бот сразу пишет и клиенту, и тебе прямо в Telegram. Если позже захочешь синхронизацию с календарём или видеозвонки с автогенерацией ссылки — это можно добавить через Google Calendar (бесплатно с личным аккаунтом) или через self-hosted Cal.com, но для старта это не нужно.

## Структура проекта

- `main.py` — точка входа, запуск бота (long polling).
- `config.py` — чтение токена и настроек из `.env`.
- `database.py` — SQLite: пользователи, слоты, брони.
- `scoring.py` — подсчёт результата теста (одиночный и смешанный тип).
- `content.py` — все тексты: вопросы, результаты, приёмы, оффер.
- `keyboards.py` — инлайн-кнопки.
- `states.py` — состояние прохождения квиза (aiogram FSM).
- `handlers/user.py` — сценарий для пользователя.
- `handlers/admin.py` — команды управления слотами для тебя.

## Установка и запуск

Понадобится Python 3.11 или новее.

```bash
python -m venv venv
source venv/bin/activate        # на Windows: venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env
```

Открой `.env` и впиши:

- `BOT_TOKEN` — токен от @BotFather;
- `ADMIN_CHAT_ID` — твой личный chat_id (узнать через @userinfobot), сюда будут приходить уведомления о новых записях.

Запуск:

```bash
python main.py
```

При первом запуске бот сам создаст файл базы данных `bot.db` рядом с кодом.

## Как добавлять слоты для записи

Все команды ниже работают только в чате с ботом от твоего аккаунта (того, чей chat_id указан в `ADMIN_CHAT_ID`).

Добавить одно окно:

```
/addslot 2026-08-25 14:00
```

Добавить несколько сразу, через запятую:

```
/addslots 2026-08-25 14:00, 2026-08-25 16:00, 2026-08-26 10:00
```

Посмотреть все окна (свободные и занятые):

```
/slots
```

Удалить свободное окно по номеру из `/slots`:

```
/delslot 3
```

Посмотреть, кто дошёл до экрана записи, но не забронировал слот дольше суток (для ручного follow-up, как описано в ТЗ):

```
/pending
```

Можно указать другой порог в часах, например `/pending 6`.

Когда пользователь бронирует слот, бот сразу присылает тебе в этот же чат сообщение с именем, username, chat_id и выбранным временем — по нему пишешь реквизиты на оплату вручную, как и было в исходном сценарии.

## Логика подсчёта результата

Реализовано ровно по разделу 3 ТЗ: считаются 8 ответов, индекс с максимумом — основной паттерн. Если максимум делят два индекса — смешанный тип, показываются оба результата по порядку первого появления в тесте, а приём — только для того паттерна, что встретился раньше. Если максимум делят три и более — берутся два самых ранних из них и дальше обрабатываются как обычный смешанный тип. Формулы проверены юнит-тестом (см. ниже).

## Что нужно от тебя до старта (обновлённый список)

Токен бота через @BotFather, твой chat_id для уведомлений, и хостинг, который работает круглосуточно — VPS, Railway, Render или похожий (без этого бот отвечает только пока запущен на твоём компьютере). Пункт про TidyCal из исходного ТЗ больше не нужен.

## Ограничения MVP

Прогресс прохождения квиза хранится в памяти процесса (aiogram MemoryStorage): если бот перезапустится посреди теста, пользователю нужно будет начать заново с `/start`. Для не бесплатного, но более надёжного варианта на будущее можно перейти на хранение состояния в той же SQLite или Redis — в текущей нагрузке (MVP, первые подписчицы) это не критично.
